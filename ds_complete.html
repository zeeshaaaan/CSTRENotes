Data Structures — Overview
A data structure is a way of organizing data in memory so it can be accessed and modified efficiently. Your notes classify them into Simple and Composite types.
Classification

Simple DS

Basic storage types: Array, Structure. Direct memory allocation, fixed size.

Composite — Linear

Sequential access: Stack, Queue, Linked List. Elements arranged in order.

Composite — Non-Linear

Hierarchical/network: Tree, Graph. Elements can have multiple connections.

DSA Operations

Insertion · Deletion · Searching · Sorting · Updation · Traversal (Data Process)

Memory Management

Stack Memory

4th Gen computers use Stack for data storage. Used by function calls, recursion, and local variables. LIFO access.

Heap Memory

Linked lists use Heap/Buffer memory. Dynamic allocation. Size not fixed at compile time.

Complexity & Asymptotic Notation
Algorithm analysis uses asymptotic notation to describe how time and space grow with input size. Time-Space trade-off: faster → more space; less space → slower.
Notations

Big O — O(n)

Upper bound — Worst-case complexity. "At most this slow."

Omega — Ω(n)

Lower bound — Best-case complexity. "At least this fast."

Theta — Θ(n)

Tight bound — Both upper & lower. Used for average case.

Little o / ω

o(g(n)): strictly smaller than upper bound. ω(g(n)): strictly larger than lower bound.

Algorithm Analysis Types

Input Size

How much data the algorithm can handle. Affects time & space.

Output

The solution an algorithm produces for a problem.

Best Case

Minimum operations needed. Ideal input scenario.

Worst / Average Case

Maximum or typical operations. Most practically relevant.

Stack
LIFO (Last In, First Out) data structure. Think of a stack of plates — you add and remove from the top only.
Key Properties

LIFO

Last element inserted is the first to be removed. One end (top) for both operations.

Operations

Push — insert at top. Pop — remove from top. Peek — view top. isEmpty — check empty.

Memory

4th Gen computers use Stack for data storage. Also used for function call management.

Applications

Undo/Redo · Recursion · Tower of Hanoi · Expression evaluation · Graph/Tree traversal

Queue
Abstract Data Structure — FIFO (First In, First Out). Insertion at Rear, Deletion at Front. If n elements, max index = (n-1).
Types of Queue

1. Input Restricted

Deletion from both sides, but insertion from one side only.

2. Output Restricted

Insertion from both sides, but deletion from front end only.

3. Double-Ended (Deque)

Insert and Delete from both sides. Most flexible queue type.

4. Priority Queue

Each element has own priority number. Two modes: Ascending (delete in ascending order) and Descending. Used for CPU scheduling.

5. Circular Queue

Front and Rear connected to each other. Also called Ring Buffer. Solves wasted space problem of linear queue.

Linked List
Linear data structure where elements (nodes) are in sequence. Each node has a Data Element + Next Pointer (address of next node). Last node's next pointer is NULL. Memory allocation using Heap/Buffer. Easy to insert.
Types of Linked List
Singly Linked List: Forward direction only (one-way). Each node has Data + Next pointer.

Properties

Singly LL

Forward direction only. Each node: [data | next→]. NULL at end.

Doubly LL

Each node has 3 elements. Direction: forward & backward. Contains [prev | data | next].

Circular LL

Last node's next pointer contains address of first node. Forms a loop.

Doubly Circular

Both directions + circular. Last node points to first, first's prev points to last.

Trees
Non-linear, hierarchical data structure. Root is topmost node. Leaf nodes have no children. Internal nodes have at least one child. Degree = total child nodes.
Types of Trees
General Tree: No constraint. Unbalanced. Superset of every tree. Node may have infinite children.
Tree Terminology

Root

Topmost node. Has no parent.

Key

Value stored in a node.

Internal Node

Node that contains at least one child node.

Leaf Node

Node with no children. Also called external node.

Degree

Total number of child nodes a node has.

Height vs Depth

Height: longest path from node to leaf. Depth: distance from root to node.

Graph
Collection of Nodes and Edges. G = (V, E) where V = set of vertices, E = set of edges. Connected path called a node. Nodes also called vertices.
Types of Graphs
Undirected Graph: No direction on edges. Bidirectional. e₁={A,B} means both {A,B} and {B,A}.
Graph Terminology

Walk

Moving from one node to another. Open walk (different start/end) or Closed walk (same start/end).

Trail

A path where edges cannot be repeated but nodes/vertices can be repeated.

Circuit

A type of closed trail. Closed trail = Circuit = Cycle.

Loop

Single edge used to connect the same node. A→A.

Degree of Node

Total connected edges. Types: Degree (all), In-degree (inward edges), Out-degree (outward edges).

Adjacent Nodes

Two different nodes connected to a single node. They share a common neighbor.

Graph Representation

Adjacency Matrix (2D Array)

Rule 1: If node has neighbour → degree = 1. Rule 2: No neighbour → degree = 0. For directed weighted graph, use weight values. Undirected: 2N nodes. Directed: N nodes.

Adjacency List (Linked List)

Use linked list. Only check connectivity, no direction check. Every node converted to linked list node. Space efficient for sparse graphs.

BFS — Breadth First Search
Traversal = A→B→C→D→E→F→G (level by level). Slower than DFS. Uses Queue (FIFO). Less memory use. Best if target node is nearest to root. First access sibling, then child. Back-tracking NOT allowed.
Steps
  • Start at root/source node, mark it visited. Add to queue.
  • Dequeue front node, process it (print/visit).
  • Add all unvisited neighbors of current node to the queue, mark visited.
  • Repeat until queue is empty.

DFS — Depth First Search
Traversal = A→B→D→E→C→F→G (depth first). Faster. Uses Stack (LIFO). More memory use. Back-tracking allowed. First child, then sibling.
Steps
  • Start at root/source node, mark it visited. Push to stack.
  • Pop top of stack, process it.
  • Push all unvisited neighbors to stack, mark visited.
  • Repeat. If stack empty and unvisited nodes remain, start from next unvisited (for disconnected graphs).

Spanning Tree
A subgraph of an undirected graph that includes all nodes of the main graph, with number of edges reduced to minimum (just enough to keep graph connected). Coined by Radia Perlman. For N nodes: possible spanning trees = N^(N-2).
Key Facts

V−1 Edges

A spanning tree with V vertices always has exactly V−1 edges. 3 nodes → 2 edges (3^(3-2) = 3 spanning trees possible).

MST Algorithms

To find Minimum Spanning Tree: (i) Prim's Algo (ii) Kruskal's Algo. Applied to weighted undirected graphs.

Cost of Spanning Tree

Sum of weights of all edges. Best = less cost.

MST Property

These algorithms connect all nodes using minimum edge/overall cost. Each edge has cost/weight.

Prim's Algorithm O(E log V)
Greedy algorithm to build MST. Start from any arbitrary vertex. After choosing a vertex, examine costs of edges to adjacent vertices and connect the vertex with minimum cost edge. Repeat until all vertices connected. Do not form any cycle. It traverses one vertex for more than one time to get min distance (First Node then Edge).
Algorithm Steps (from notes)
  • Remove all cycles, loops & parallel edges.
  • Choose any arbitrary vertex as Root Node and start creating MST.
  • Check outgoing edges & choose the edge having minimum cost.
  • Add that vertex to visited set. Add its edges to priority queue.
  • Repeat until all vertices are connected. Never form a cycle.

Kruskal's Algorithm O(E log E)
To find MST: pick the edge with smallest cost first, then next smallest-cost edge. Continue until all vertices are connected to the MST. Do not create any loop & cycle. Traverse one vertex once only. Edge first, Node last.
Steps
  • Sort all edges by weight ascending.
  • Initialize each vertex as its own component (Union-Find).
  • Pick smallest cost edge — if it doesn't form a cycle, add to MST.
  • If it creates a cycle, skip it.
  • Repeat until V−1 edges are added to MST.

Sorting — Concepts
Arranging elements in ascending or descending order. Your notes cover 3 patterns for classifying sorts.
Pattern A: Inplace vs Non-Inplace

Inplace Sorting

No extra memory required. Sorts within the original array. Examples: Bubble, Insertion, Selection, Quick.

Non-Inplace Sorting

Extra memory required for sorting. Examples: Merge Sort O(n) extra space.

Pattern B: Stable vs Unstable

Stable Sorting

While sorting, order of equal elements does NOT change. Examples: Merge Sort, Insertion Sort, Bubble Sort.

Unstable Sorting

Order of equal elements CAN change. Examples: Quick Sort, Selection Sort.

Pattern C: Adaptive vs Non-Adaptive

Adaptive Sorting

If positions of elements already sorted are NOT changed. Benefits from partially sorted input. Examples: Bubble Sort, Insertion Sort.

Non-Adaptive Sorting

Positions of already-sorted elements ARE also changed. No benefit from pre-sorted input. Examples: Selection Sort.

Bubble Sort
Simple comparison-based algorithm. Compare each element with adjacent element; if out of order, swap them. Like bubbles in soda, elements bubble to their correct positions. After each pass, largest element settles at nth position, then next largest at n-1, so on.
Key Points from Notes

Pass terminates

Pass will terminate if each step has no swap. Early exit optimization.

Complexity

Best/Average/Worst = O(n²). If already sorted → O(n). Not preferable for big data.

Inplace & Stable

Sorts in-place (O(1) space). Stable sort — equal elements maintain relative order.

Passes = n−1

Comparisons per pass decrease by 1 each time. Total comparisons ≈ n(n-1)/2.

Selection Sort
Simple inplace sorting algorithm. Repeatedly find the smallest element in the unsorted region and swap it with the current position. Continue until entire array is sorted. Passes = (n-1). Comparisons = n(n-1)/2.
Key Points

Minimum Swaps

Makes exactly n−1 swaps regardless of input. Good when writes are expensive.

Complexity

Best, Average, Worst = O(n²). Space = O(1). Not adaptive.

Insertion Sort
Maintains a growing sorted sublist. For each element, scan leftwards through the sorted part to find its correct position and insert it. Starts from the second element (first is considered sorted). Inplace and Stable. Adaptive.
Key Points

Best Case O(n)

When already sorted. Only n−1 comparisons, no shifts needed.

Average/Worst O(n²)

Reverse sorted input causes maximum shifts.

Merge Sort
Divide and Conquer method. Most efficient algorithm. Best, Average, Worst → O(n log n). Merging Complexity = O(n). Stable Sorting. Not inplace (needs O(n) extra space).
Steps
  • If array has 0 or 1 elements, return (base case — already sorted).
  • Divide array into two halves at midpoint.
  • Recursively merge-sort the left half.
  • Recursively merge-sort the right half.
  • Merge the two sorted halves by comparing elements front-to-front.

Quick Sort
Divide the array into two parts using a pivot (rightmost element used). Elements on left are less than pivot, elements on right are greater. Recursively quick-sort left and right partitions. Order after partition: lesser element < Pivot < greater elements. Inplace sorting. Not Stable, Not Adaptive.
Key Points

Best/Average: O(n log n)

Good pivot selection is key to performance.

Worst: O(n²)

Occurs when wrong pivot is selected (e.g., already sorted array, pivot = first/last).

Searching
Finding a target element in a data structure. Two main methods covered in your notes: Linear Search and Binary Search.
1. Linear Search

How it works

Target element searched sequentially until found. Matched against every element. Works on both sorted and unsorted data.

Complexity

O(n). Best case O(1) if target is first element. Space = O(1).

2. Binary Search

How it works

Works ONLY on sorted array. Compare target with middle element. If equal → return index. If target < middle → search left subarray. If target > middle → search right subarray.

Complexity

O(log n). Best for large number of elements. Space = O(1) iterative, O(log n) recursive.

Expression Evaluation
Combination of arithmetic operators & operands/variables. Operators solved based on precedence: ↑(Power) highest → /, * next → +, − lowest. Brackets solved first.
Three Notations

Infix (A+B)

Operator between operands. Standard human-readable form. Requires precedence rules. E.g.: (A+B)*C

Prefix / Polish (+AB)

Operator before operands. No brackets needed. E.g.: *+ABC

Postfix / RPN (AB+)

Operator after operands. Also called Reverse Polish Notation. E.g.: AB+C*

Precedence

Higher: ^ (Power) → Next: /, * → Lowest: +, −. Brackets solved first.

Shortest Path & Advanced Topics
Advanced graph algorithms, multi-stage graphs, NP problems, and classical algorithmic problems from your notes.
Shortest Path Algorithms

Floyd-Warshall

All Pairs Shortest Path (APSP). Calculates shortest path between all pairs of vertices. Works with negative weights (no negative cycles).

Dijkstra's Algorithm

Single Source Shortest Path. No negative weights. Time complexity: O(V²) adjacency matrix, O(V+E log V) with adjacency list.

Multi-Stage Graph

Graph whose vertices are divided into multiple levels. Edges go only from one stage to the next. Example: Shortest-path problem.

All Trees are Graphs

but not all graphs are trees. Trees have no cycles, graphs can.

Classical Problems

8-Queen Problem

Place 8 queens on a chessboard so no two attack each other. Constraint: no two queens share same row, column, or diagonal. Approach: use Backtracking.

Hamiltonian Problem

From graph theory. Determine if a graph has a path visiting every node exactly once, and possibly a cycle returning to start. Hamiltonian Path visits every vertex once. Hamiltonian Cycle visits every vertex once and returns to start.

NP — Non-Deterministic Polynomial Time

What is NP?

Problems whose solution can be verified in polynomial time. Finding the solution may take exponential time.

NP-Hard

Traveling Salesman Problem (TSP), 3D matching. At least as hard as NP problems.

NP-Complete

SAT, Hamiltonian Cycle, Clique, Vertex Cover, 0/1 Knapsack. Both NP and NP-Hard.

AVL Tree BF

Balance Factor = Height of Left Subtree − Height of Right Subtree. Valid BF = {−1, 0, +1}. Self-balancing (Adelson-Velski & Landis).
